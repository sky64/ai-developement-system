# scout64 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship `scout64`, a Haiku read-only helper agent, make it the default for search, reading and summarizing, and put it behind a switch.

**Architecture:** One new plugin agent file; one boolean switch in the config reader (optional in validation, like `limits`); a rule change in the orchestrator skill and docs/05; pins and tests. No hook change.

**Tech Stack:** Markdown agent file, Python 3.13+ standard library, bash, `claude plugin validate`.

**Spec:** `docs/decisions/0008-scout64.md`

**Branch:** `sky64/scout64` from main (worktree `~/orca/workspaces/ai-developement-system/scout64`, already created with the spec and this plan committed). Execute this plan before the process-ladder plan; that one branches from main after this PR merges.

## Global Constraints

- Risky tier (orchestrator skill, docs/05, config reader): rung 2, Codex review at `--effort high`, Runtime floor Python 3.13+ and bash on Linux.
- `features.scout64` default true; missing key reads as true and validates; non-boolean falls back to true and `check` names `features.scout64`.
- The agent file carries `model: haiku`; the orchestrator reports `models.research[0]` beside it and names a deviation when the family differs.
